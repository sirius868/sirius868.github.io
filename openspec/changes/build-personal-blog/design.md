# Design

## Context

参见 [proposal.md](proposal.md) 的动机与范围。当前仓库只有 OpenSpec 目录，没有应用代码、内容、测试、部署配置或主规格，因此可以为静态博客选择简单的起点。参考站公开页面表现出宽松的留白、居中的阅读区域、顶部导航、浅色/深色主题、文章与关于页面；本项目借鉴这些布局原则，不复制其代码、内容、品牌或插画。页面行为以本变更的五份规格为准。

## Goals / Non-Goals

**Goals:**

- 构建无需运行时服务器的可发布站点，文章由版本控制中的文件管理。
- 将作者资料、站点名称、站点地址和社交链接集中配置，便于替换而不改页面结构。
- 让文章、搜索、订阅和元信息共享同一套发布规则，避免草稿泄露。
- 保持内容优先的响应式视觉，组件与设计变量可扩展。

**Non-Goals:**

- 提供在线编辑器、账号系统、数据库、评论服务或联系表单。
- 复刻参考站的特定动画角色、文案、图片、配色数值或完整栏目结构。
- 在本次规划中选定托管平台或购买域名。

## Decisions

### 1. 使用 Astro 与 TypeScript 生成静态站点

Astro 的内容集合、静态路由和少量客户端脚本适合文章型网站。默认使用静态输出，首页、文章列表、标签页、文章详情、关于、RSS 和站点地图在构建时生成。搜索和主题控件是唯二主要客户端交互。备选的 Next.js 会引入更多运行时与部署选择；纯手写 HTML 难以维护内容集合与模板。

### 2. 文章与作者资料分离管理

文章存于 `src/content/blog/` 的 Markdown/MDX 文件，内容集合校验 `title`、`description`、`pubDate`、`tags`、`featured`、`draft` 等字段；文件标识或显式 slug 必须唯一。作者名称、简介、经历、社交链接和站点 URL 存于集中配置文件。所有公开页面通过统一的“已发布文章”查询生成，避免首页、搜索、RSS 和站点地图采用不同过滤规则。文章列表每页固定数量，页码与标签使用可直接打开的静态 URL。无真实资料时，开发预览使用清楚标记为示例的内容；发布前用检查清单替换。

### 3. 搜索在构建时生成轻量索引

构建时仅抽取已发布文章的标题、摘要、标签和纯文本正文，输出静态 JSON 索引；搜索页在用户输入时加载索引，并在浏览器中匹配中文连续字符与不区分大小写的英文关键词。结果 URL 使用查询参数，支持复制和刷新。备选的第三方搜索服务需要外部依赖与索引同步；仅搜索标题会遗漏正文内容。若文章数量明显增长，再评估分词索引或独立搜索服务。

### 4. 以设计变量建立独立视觉语言

采用用户指定的白色主调，以黑色系呈现文字、按钮和细节，灰色用于层次区分；明确字体层级、适度圆角和宽松间距。正文控制最大宽度，首页可使用更宽的内容容器。共享页头、导航、页脚、文章卡片、标签与主题控件；在小屏幕上折叠导航，保持搜索和主题入口可达。首页抽象图案使用缓慢的轨道旋转、中心浮动与星点呼吸动效。主题有 `light`、`dark`、`system` 三种偏好，首次访问默认为白色浅色主题，页面加载前解析偏好以减少闪烁，存储失败时回退为当前页状态。动效遵守减少动态效果偏好，关闭时保留完整静态图案。备选的直接套用参考站样式容易造成视觉复制与后续维护负担。

用户提供的 yh 标识裁切透明留白后用于页头和 favicon。首页主按钮用鼠标位置驱动局部流光，触屏与减少动态效果环境保持静态。页头在滚动后收为浮动工具栏；向下滚动隐藏、向上滚动或返回顶部显示，菜单展开及键盘焦点进入页头时保持可见。

搜索页输入区采用白色半透明玻璃层、柔和高光与背景模糊，按钮采用深色玻璃渐变和细微掠光；深色主题使用相应的深灰玻璃层。鼠标高光随指针移动，触屏及减少动态效果环境保持静态。

顶部导航各项常驻半透明玻璃底、边缘高光和轻微反光，悬停与键盘聚焦时增强材质层次；深色主题使用低亮度玻璃层。当前页的选中状态仍持续显示，减少动态效果设置下停用位移与反光过渡。各页预留稳定的滚动条空间，避免短搜索页与长文章页切换时整体横向跳动。

主题选择使用与站点一致的按钮和弹出菜单，展示当前模式与选中状态，并提供方向键、回车和 Esc 操作。用户当前没有正式域名，因此本地构建继续使用 `localhost` 供预览；正式发布前必须设置 `PUBLIC_SITE_URL` 并核查绝对链接。

### 5. 生成独立页面元信息及订阅资源

统一布局组件生成标题、描述、canonical 和 Open Graph 信息。构建配置中使用单一站点 URL，供绝对链接、站点地图和 RSS 共用；未配置正式 URL 时使用明确的本地开发值，并在发布检查中提醒替换。文章详情使用文章标题与摘要，其他页面使用各自文案。未找到页面提供回到首页和文章列表的入口。

### 6. 笔记使用独立内容集合

用户追加笔记栏目后，笔记与博客文章分开存入 `src/content/notes/`，沿用相同的 slug、必填元信息和草稿校验规则。笔记页采用更紧凑的列表样式，详情复用文章正文排版；导航新增“笔记”。笔记不进入第一版的文章搜索或 RSS，避免改变现有两者明确面向文章的范围。备选方案是将笔记混入文章集合，但会让两个栏目和发布规则难以区分。

## Risks / Trade-offs

- [作者真实资料、域名和文章尚未提供] → 配置使用显眼的示例值，发布任务中明确逐项替换并检查公开页面。
- [客户端全文索引会随文章数量增长] → 起步阶段仅含必要字段并延迟加载；若体积影响体验再升级索引方案。
- [静态站点需要重新构建才能发布文章] → 使用仓库内容文件与标准构建命令，文档写明发布步骤。
- [Markdown/MDX 中的自定义组件可能造成样式与可访问性问题] → 第一版提供少量受控的排版组件，并检查图片替代文本、标题层级和代码块溢出。

## Migration Plan

1. 初始化前端工程与构建配置，保持现有 OpenSpec 文件原位。
2. 加入内容模型、示例资料与基础页面，再接入搜索、主题和订阅资源。
3. 本地构建并核查关键路径、移动端和键盘操作；发布前替换示例内容与正式站点 URL。
4. 将静态输出部署到选定托管平台。回滚时重新部署上一版静态构建产物；本项目没有数据库迁移。
